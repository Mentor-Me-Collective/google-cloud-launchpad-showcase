# ClimateOps Mobile Field Companion App

> **Status:** Integrated Field Companion App based on the Newly Hackathon codebase, re-wired to connect directly to the Google Cloud Run ClimateOps backend API (`https://climateops-api-4twvqq3jta-uc.a.run.app/api/v1`).

The ClimateOps Mobile Field Companion App equips on-the-ground facility teams, maintenance staff, and field operations managers in the South Bronx (Mott Haven / Melrose) with a high-fidelity mobile interface for real-time risk visibility, task execution, and proof collection.

---

## Architecture & Integration with Capstone

```
┌───────────────────────────────────────────────┐
│        Google Cloud Run API Backend           │
│   (FastAPI + Firestore + NVIDIA NIM + GCS)    │
└───────────────────────┬───────────────────────┘
                        │ HTTPS (Bearer Auth)
            ┌───────────┴───────────┐
            ▼                       ▼
┌───────────────────────┐ ┌───────────────────────┐
│ Web Command Center    │ │ Mobile Field App      │
│ (Desktop Web Console) │ │ (Expo / React Native) │
│ • Manager Approval    │ │ • Field Facility List │
│ • Hazard Simulator    │ │ • Task Verification   │
│ • NIM Brief Inspector │ │ • GCS Proof Upload    │
└───────────────────────┘ └───────────────────────┘
```

### Key Alignment with Capstone ADRs
- **ADR-001 (Human Approval Gate):** In accordance with ADR-001, field staff can inspect prioritized facilities and drafts, but task creation and execution workflows are strictly locked until a designated facility manager formally approves the readiness brief on Cloud Run.
- **ADR-004 (Deterministic Facility Scoring):** The mobile priorities feed reflects the identical deterministic risk formula computed by the Cloud Run backend (`heat_score + vulnerable_pop + ac_failure + occupancy + staffing_risk`), ensuring consistency between web command center and field workers.
- **ADR-008 (Direct Cloud Storage Upload):** Uploading photo proof (e.g. generator inspection tags, HVAC status) utilizes GCS signed upload URLs generated by Cloud Run.

## Features

1. **Prioritized Facilities Feed:**
   - Real-time facility risk ranking mapped from `GET /api/v1/priorities` on Cloud Run.
   - Dynamic risk factor breakdowns (Heat Vulnerability Index, AC operational status, vulnerable population census).
   - High-contrast visual priority badges (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`).

2. **Readiness Briefing Viewer:**
   - Displays NVIDIA NIM-generated evidence-cited briefings fetched from Cloud Run (`POST /api/v1/briefs/generate` or `GET /api/v1/briefs/current`).
   - Grounded citations linking directly to National Weather Service alerts and NYC DOHMH HVI records.
   - Visual disclaimer tag: `[DEMO/SIMULATED DATA]`.

3. **Weather & Heat Alert Radar:**
   - Synchronized with NWS forecast endpoints via `GET /api/v1/weather/status`.
   - Displays real-time temperature, heat index, and active NWS advisory flags.

4. **Resilient Offline Fallbacks:**
   - Seamless fallback fixtures (`OFFLINE_FALLBACK_FACILITIES`) loaded if disconnected or during offline field inspections in basements and shielded structures.

## Development Setup

### Prerequisites
- Node.js 18+ or Bun
- Expo Go app on your physical iOS/Android device or a local simulator

### Installation & Run

```bash
# 1. Navigate to the mobile directory
cd mobile

# 2. Install dependencies
npm install
# or
bun install

# 3. Start Expo development server
npx expo start
```

Press `i` for iOS Simulator, `a` for Android Emulator, or scan the QR code with Expo Go.

### Environment Configuration

The app defaults to the deployed Cloud Run instance:
```bash
EXPO_PUBLIC_CLIMATEOPS_API_URL=https://climateops-api-4twvqq3jta-uc.a.run.app/api/v1
EXPO_PUBLIC_CLIMATEOPS_AUTH_TOKEN=demo-manager-a
```
To target a local backend running `make run`, update `.env`:
```bash
EXPO_PUBLIC_CLIMATEOPS_API_URL=http://localhost:8080/api/v1
```
